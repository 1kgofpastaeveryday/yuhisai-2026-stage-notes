# SETSTOPの拍表示・単体テスト

10/27、実際の小講堂1日目の12演目に対応し、文字を演目名だけにした[受信テスト版](../live-countdown/README.md)を作成した。現在はこちらを使う。以下は仮データ版の検証記録。

2026-10-26更新。iPad縦向き744×1133の試験版。開くファイルは[setstop-countdown-demo.tosc](setstop-countdown-demo.tosc)。仮の12演目・48曲・12停止点を使う。時計と再生位置はTouchOSC内のLuaで動かす。



## 表示

中央の4つの大きな光が拍に合わせて進む。上の帯は次の停止点までの区間を示し、再生に合わせて短くなる。下の16マスは最後の16拍で1つずつ消える。

再生中に残り16拍へ入ると、演目一覧や曲一覧から大きなカウント画面へ自動で切り替わり、外周が黄色になる。最後の4拍は外周と中央が赤くなり、大きな光も1つずつ消える。停止点に到達すると大きな「SETSTOP」と外周を保ち、停止を示す。

最後16拍の再生中はカウント画面を固定する。停止後は「演目」から一覧へ戻れる。手動の再生停止・続きから再開・QLC+全停止は共通の位置にある。

仮データは4/4で、4分音符を1拍としている。テンポ変更では光の進む速さが変わる。本番で使う拍子や拍の取り方は、完成したセトリに合わせて確認する。

## 試し方

1. TouchOSCでファイルを開き、操作画面へ切り替える。最初は大きなカウント画面が開く。
2. 「テスト 続きから再開」を押す。中央の光と帯が動く。
3. 「16拍前」「4拍前」で停止点の手前へ移動し、光が減る様子を確認する。
4. 「SETSTOP」が出たら再開する。次の停止点を対象に進む。
5. 「演目」から演目と曲を選ぶと、その曲頭の仮位置へ移動する。曲の再タップは選択だけを解除し、再生位置は変えない。一覧の「カウント」で大きな表示へ戻る。

停止中は光と帯も止まる。再生中の頭出しは再生を継続する。最後の停止点を通過すると「終了」を表示する。

## 検証結果

[verification.json](verification.json)に、生成した84本のLuaの模擬実行結果を保存した。

- 拍に合った光の移動と帯の縮小、途中停止・再開。
- 残り16拍の自動表示と黄色の外周、残り4拍の赤色と大きな光の消灯。
- 停止点での表示保持、停止後の演目選択、再開後の次の停止点への切り替え。
- 演目02内の90→180 BPM変更と、拍を基準にした残量表示。
- 48曲への前後の頭出し、選択解除、全14画面の往復。
- 拍の途中にある停止点、境界ちょうどの更新、最後の停止点。
- 83個のタッチ領域の大きさ・画面内配置・重なり、55件のMIDI送信無効、OSC送信設定なし。

[native-verification.json](native-verification.json)にはMacのTouchOSC本体の結果を保存した。最終ファイルの読み込み、744×1133のサイズ、84本のLuaコンパイルと55件のMIDI無効を確認した。アプリがダイアログ表示中と返すため、操作画面での実行は未確認。

本物のLiveから再生位置・停止状態・ロケーターを受信する処理は未実装。ClyphX停止との連動とiPad実機は未確認。試験版の停止はLuaが行う。元のLiveセットと[既存の操作画面](../prototype/README.md)は変更していない。

## 再生成

```powershell
python yuhisai-2026/touchosc/build_countdown_demo.py
python yuhisai-2026/touchosc/verify_countdown_demo.py
```

生成にはPillow、検証にはLupaが必要。[生成スクリプト](../build_countdown_demo.py)が仮ロケーターとテンポ表を作り、[countdown_demo.lua](../countdown_demo.lua)を文書へ埋め込む。[demo-timeline.json](demo-timeline.json)は仮データの確認用。

模擬実行には[テスト用のTouchOSC制御ツリー](../countdown_test_runtime.py)を使う。Luaのコントロール値・色・可視状態・配置から静止画とGIFを描き、検証対象のロジックとプレビューの動きを合わせている。
