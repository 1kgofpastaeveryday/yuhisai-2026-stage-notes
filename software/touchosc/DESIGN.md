# 演者用の再生画面のデザインのきまり（TouchOSC）

この文書は10/18のRUMY演者用試作の記録。10/25に本人が指定した12演目・iPad縦向きの操作画面は、[マニピュレーター運用](../operations/playback/legacy-setup.md)に従って[別のプロトタイプ](prototype/README.md)を作った。演目内の各曲の頭出し、続きから再開、QLC+全停止を含む。以下の「待機ロケーターへ飛ぶ停止」と既存の`build_layout.py`・見本は、その新しい運用へ更新済みという意味ではない。

10/18 に Claude が作った下書き。RUMY がステージの iPad で、自分のタイミングで曲を流したり止めたりする画面のための土台で、ほかの団体にも使い回せるようにしてある。見本の画面は [sample.png](sample.png)、作るスクリプトは [build_layout.py](build_layout.py)、見本の中身は [layouts/sample.json](layouts/sample.json)。TouchOSC の仕組みと接続の手順は [../touchosc-notes.md](../touchosc-notes.md)。

![見本の画面](sample.png)

## 前提

- 使う人は、ステージ上で歌っている2人。両手かどちらかの手にマイクを持ち、暗いステージで、曲の合間に一瞬だけ画面を見る。
- 端末は iPad mini（第6世代以降、縦向き）。画面の大きさは 744×1133 ポイントで、文書も同じ大きさで作る。
- TouchOSC には画像を置く部品がなく、フォントも標準と等幅の2つしかない（公式マニュアル）。そのため Material Icons のフォントは使えない。アイコンは、Material Symbols の形を TouchOSC の図形（四角、丸、三角）で組み直して作る。⏮ ⏭ ⏹ などの記号は Mac の TouchOSC で表示されず（10/18 確認）、iPad で出るかも分からないので、文字の記号には頼らない。

## 原則

1. 1回見て、1回押す。メニューも切り替えのモードも作らない。どのボタンも、押せばすぐその動作になる。
2. 形と言葉と色の3つで伝える。色だけに頼らない。アイコンの形で動作を、日本語で中身を示し、色はその裏付けにする。
3. 曲がひとまとまり。曲ごとにカードを作り、最初から流すボタンと途中から流すボタンを同じカードに入れる。どの曲のボタンか迷わない。
4. 停止はいつも同じ場所。画面の下の端に横いっぱいに置き、曲のボタンとは離す。
5. 画面は暗く、静かに。背景を暗くして、客席に iPad の光が漏れないようにする。明るいのは押せるところだけ。
6. 演者に関係ないものは置かない。音量、ミキサー、設定は出さない。

## トークン

| 種類 | 値 |
|---|---|
| 余白 | 外側24、部品の間16、カードの内側16（8の倍数で組む） |
| 押す場所の大きさ | 最初から：280×104。途中から：210×80。停止：696×112。どれも Apple の推奨（44ポイント以上）の2倍以上 |
| 背景 | `#0D0E11` |
| カード | `#1A1D23`（途中からのチップは `#272B34`） |
| 文字 | 主 `#F5F5F5`、副 `#A0A6B0` |
| 最初から | 緑 `#1FA463` |
| 途中から | 青 `#3D8BFF` |
| 停止 | 赤 `#E5484D` |
| 押したとき | 白を35%重ねて光らせる |
| 文字の大きさ | 曲名36、最初から32、途中から26、停止44、凡例22 |

## アイコン

| 動作 | Material Symbols の名前 | 組み方 |
|---|---|---|
| 最初から | `play_arrow` | 右向きの三角 |
| 途中から | `resume` | 縦の棒（頭出しの印）と右向きの三角 |
| 停止 | `stop` | 角を少し丸めた四角 |

途中からに `skip_next`（▶|）や `fast_forward`（▶▶）を使わないのは、「次の曲へ」「早送り」と読めてしまうからである。`resume` は、印のところから再生する、と読める。

## 部品

- 凡例（画面の上）：団体名と、3つのアイコンの意味。初めて見た人も、アイコンの意味が画面の中で分かる。
- 曲カード：番号、曲名、最初からのボタン（右）、途中からのチップ（下の段、1曲に3つまで並ぶ）。途中からがない曲は、カードの高さが縮む。
- 途中からのチップ：`resume` のアイコン、区間の名前、曲のどのあたりかを示すバー。
- 停止バー：画面の下の端に横いっぱい。
- 押す場所は、見た目の部品の上に重ねた透明なボタンで、押したときだけ白く光る。

## 途中から再生をどう示すか

| 案 | 中身 | 評価 |
|---|---|---|
| A（採用） | 区間の名前（サビ、2番など）のチップに、`resume` のアイコンと、曲のどのあたりかを示すバーを付ける | 演者は曲を区間の名前で覚えているので、名前がそのまま押す理由になる。バーは Material のシークバーと同じ見た目（塗りと丸いつまみ）で、「この位置から」と読める |
| B | 曲ごとに時間の線を描き、飛び先の印を押す | 見た目は直感的だが、印が小さくて押し間違えやすい。好きな位置へ動かせるように見えるが、実際は決めた位置にしか飛べない |
| C | 「途中から」の切り替えを押してから、曲を選ぶ | モードがあると、切り替えたまま忘れて事故になる（原則1） |
| D | 「1:23から」のように時刻で書く | 演者は時刻で曲を覚えていない |

区間の名前は、RUMY が普段使っている呼び方をそのまま使う。飛び先を決めるときに、名前もあわせて聞く。

## 状態

- 押したとき：白く光る（作り済み）。
- 再生中（未実装）：再生中の曲のカードの縁を白くし、「再生中」と出したい。Live から iPad に今の再生位置を返す必要があり、返せるかは確かめていない（../touchosc-notes.md の未確認）。

## 10/18の試作のMIDI割り当て

チャンネル1で、押したときに音符を1つ送る。Live では、それぞれをアレンジメントのロケーターに MIDI マップする。本番は全編アレンジメントで回す（10/18 本人決定）。再生を流したまま、クオンタイズを「なし」にしてロケーターへ飛ぶ形で、挙動は ../touchosc-notes.md の「ロケーターで飛ばす」で確かめた。

| 動作 | 音符 | Live の割り当て先 |
|---|---|---|
| 停止 | 36 | 無音の「待機」のロケーター（Live の停止ではない） |
| 曲 n（1から数える）を最初から | 60 + 8×(n−1) | 曲 n の頭のロケーター |
| 曲 n の k 番目の途中から | 60 + 8×(n−1) + k（kは1〜7） | その区間の頭のロケーター |

曲を足しても、ほかの曲の番号は変わらない。build_layout.py は作ったあとに、この対応表を出す。

## 作り方

1. TouchOSC（デスクトップ版）を `open -a /Applications/TouchOSC.app --args --mcp.enabled=true --editor.network.state=SERVER` で起動する。
2. layouts/ に曲の一覧の JSON を書く（`title`、曲ごとに `title` と `jumps`。`jumps` は `label` と、曲のどのあたりかを0〜1で書く `position`）。
3. `python3 build_layout.py layouts/<ファイル>.json` を実行する。開いている文書の中身はすべて置き換わる。
4. iPad の TouchOSC から Editor Network で Mac につなぐと、同じ画面が映る。切ったあと iPad で保存する。

縦に収まらない曲数（途中からの多さによるが、4〜5曲が目安）になったら、スクリプトは止まる。そのときはページに分ける方法を決める（未決）。
